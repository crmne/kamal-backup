## Download a database dump without restoring

kamal-backup 1.1 adds `dump`, which downloads one database dump file from a backup to your machine. Use it when you want the raw PostgreSQL, MySQL, MariaDB, or SQLite dump to inspect, load somewhere else, or keep, without running a full restore.

```sh
bundle exec kamal-backup dump latest -o tmp/app.pgdump
```

![kamal-backup dump --help](https://github.com/user-attachments/assets/0170afc5-fb99-4caa-80ee-09ba42cf12f0)

### New

- **`kamal-backup dump [snapshot-or-latest] -o PATH` downloads one database dump.** From an app checkout it streams the dump from the backup accessory over SSH, using the accessory's mounted repository config and the SSH user, port, proxy, and keys from `config/deploy.yml`. Repository credentials stay off the SSH command line. An existing output file is left alone unless you confirm or pass `--yes`, and `--database NAME` picks one database when several are configured. By @pkayokay in #27.

### Fixed

- **Explicit snapshot IDs restore the whole backup.** Each backup writes one snapshot per database and one for files, so `restore` and `drill` with an ID from `list` always failed for one of them. They now resolve every part from the same backup run, and stop before restoring anything when that backup is incomplete. Reported by @maciej-sokolowski in #23.
- **Remote commands work when `config/deploy.yml` sets an SSH proxy.** Kamal renders `ssh.proxy` and `ssh.proxy_command` as Ruby objects that kamal-backup could not read, so every remote command failed on a proxied deploy. Found while reviewing #27.

### Install

```ruby
gem "kamal-backup", "~> 1.1"
```

The accessory image is `ghcr.io/crmne/kamal-backup:1.1.0`, and the stable `latest` tag now points to 1.1.0. Run `bundle exec kamal-backup dump --help` or read the [restore guide](https://kamal-backup.dev/restore/) for every option.
